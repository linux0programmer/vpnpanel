# VPN Server Panel

Самостоятельный VPN-роутер на Ubuntu: сервер с двумя (и более) сетевыми картами раздаёт локальной сети интернет исключительно через VPN-туннель, а управляется через веб-панель.

## Что внутри

| Каталог | Что это |
|---|---|
| [`installer/`](installer/) | Установщик `install.sh`, диагностика `diagnostic.sh` и документация к ним |
| [`panel/`](panel/) | Веб-панель (PHP 8 + vanilla JS), демон отказоустойчивости, деплой и маршрутизация каналов |

Подробности — в [installer/README.md](installer/README.md) и [panel/README.md](panel/README.md), диагностика по секциям — в [installer/docs/diagnostic.md](installer/docs/diagnostic.md).

## Установка

Нужны Ubuntu 22.04/24.04 и минимум две сетевые карты: одна смотрит к провайдеру (WAN), вторая — в локальную сеть (LAN).

```bash
curl -fsSL https://raw.githubusercontent.com/linux0programmer/vpnpanel/main/installer/install.sh -o install.sh && sudo bash install.sh
```

Больше ничего скачивать не нужно: установщик сам заберёт код панели — и сделает это **до** того, как тронет сетевые настройки, чтобы неудачная конфигурация не оставила сервер без сети и без кода одновременно.

Другие способы, если первый не подходит:

```bash
git clone https://github.com/linux0programmer/vpnpanel.git && sudo bash vpnpanel/installer/install.sh
```

Если на сервере нет доступа к GitHub — скопируйте каталог проекта любым способом и запустите `installer/install.sh` из него: панель возьмётся из соседней папки `panel/`, сеть для установки не нужна.

Установщик спросит, какие карты использовать, предложит добавить резервных провайдеров и даст выбрать режим WAN: DHCP, статика вручную, **оставить текущие настройки** или **закрепить текущий адрес статикой** — последнее снимает проблему прыгающего по DHCP адреса, не заставляя ничего вводить.

## Что делает панель

- **VPN-менеджер** — несколько конфигов WireGuard и OpenVPN, приоритеты, переключение, автоматическое восстановление
- **Kill Switch** — политика `FORWARD DROP`, локальная сеть физически не может выйти мимо туннеля
- **Несколько провайдеров** — список каналов с приоритетом, policy routing по таблице на канал, переключение при отказе линии
- **Мониторинг** — нагрузка, скорость и трафик по интерфейсам, журнал событий
- **Диагностика и консоль** — пинг через выбранный интерфейс, веб-терминал
- **Обновления** — по тегам, со снимком перед выкладкой и автоматическим откатом при провале проверки
- **Управление парком** — панели раз в час читают `release.conf` из репозитория: там задаётся тег релиза, стоп выкатки, процент канарки и откат всего парка

## Одна версия — номер выпуска

На сервере ровно одно число: **номер выпуска**, тег `vN` из репозитория. Он лежит в `/var/www/version`, точная ссылка с хешем — в `/var/lib/vpn-panel/deployed`. Установщик ставит выпуск, названный в `release.conf`; деплойщик обновляет его же.

Большинству выпусков достаточно заменить файлы в `/var/www/html`. Но если выпуск требует **одноразового действия на сервере** — дописать ключ в конфиг, создать юнит, — в `update.sh` добавляется блок:

```bash
if [ "$CURRENT_RELEASE" -lt 12 ]; then
    ...то, что должно случиться один раз при переходе на 12-й выпуск...
fi
```

Сервер, стоявший на 3-м выпуске и прыгнувший на 12-й, выполнит все такие блоки между ними.

**Правило для этих блоков:** только добавлять, никогда не ломать старый код. Иначе откат кабинета сломает панель — код будет искать старое, а на сервере уже новое. И блок должен быть безвредным при повторе: после отката и возврата он выполнится ещё раз.

## Что возвращает откат

`vpn-panel-deploy rollback` восстанавливает из снимка не только `/var/www/html`, но и файлы, которыми владеет панель:

```
/etc/vpn-panel.conf                          /etc/dnsmasq.conf
/var/www/settings                            /etc/iptables/rules.v4
/etc/netplan/99-vpn-panel.yaml               /etc/systemd/system/vpn-healthcheck.service
/etc/sudoers.d/vpn-panel-www-data            /etc/systemd/system/vpn-panel-routing.service
```

Sudoers перед установкой проверяется через `visudo`, netplan применяется только если файл изменился, iptables восстанавливаются из вернувшегося `rules.v4`.

Чего не вернёт никакой снимок: установленные пакеты, правки PAM, `sysctl`, `modprobe`. Они и не зависят от выпуска — `update.sh` приводит их к нужному виду при каждом запуске. Если нужно вернуть сервер целиком в прошлое состояние, это снимок виртуальной машины или переустановка, а не деплойщик.

## Обслуживание

```bash
sudo vpn-panel-deploy check          # что развёрнуто, что доступно, что говорит манифест
sudo vpn-panel-deploy deploy         # обновиться немедленно
sudo vpn-panel-deploy rollback       # вернуться на предыдущий снимок

sudo vpn-panel-routing status        # каналы в интернет и их состояние
sudo vpn-panel-routing add-wan ens36 # добавить провайдера без переустановки

sudo bash diagnostic.sh              # ~80 проверок состояния сервера
```

Ключевые настройки сервера лежат в `/etc/vpn-panel.conf`: интерфейсы, список каналов, параметры локальной сети, канал обновлений.
Там же `PANEL_TITLE` — что писать в заголовке вкладки браузера. Пусто — нейтральное «Вход» и «Панель»: страница входа намеренно не сообщает, что это за система и чей пароль спрашивает. Что разворачивать на всём парке — в [`release.conf`](release.conf).
