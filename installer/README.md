# VPN Server Panel

> VPN-роутер для дома и офиса с веб-панелью управления.
> WireGuard + OpenVPN, автоматический failover, Kill Switch, веб-терминал, мониторинг в реальном времени.

## Команда для запуска установщика

```bash
curl -fsSL https://raw.githubusercontent.com/linux0programmer/vpnpanel/main/installer/install.sh -o install.sh && sudo bash install.sh
```

## Что это

VPN Panel — **готовый VPN-роутер на базе Ubuntu**, который превращает обычный мини-ПК или сервер в шлюз с VPN-туннелем для всей локальной сети. LAN-устройства подключаются как обычно, а трафик уходит наружу через WireGuard или OpenVPN — прозрачно, без настройки клиентов на каждом устройстве.

Всё управление — через веб-панель: загрузить конфиг VPN-провайдера, выбрать активный, посмотреть статистику, настроить failover на резервный сервер. Если основной туннель падает — автоматическое переключение за 5 секунд. Если VPN недоступен совсем — Kill Switch блокирует выход в интернет, чтобы реальный IP не утёк.

**Подходит для:**
- Домашней сети, чтобы все устройства (ТВ, смартфоны, IoT) были за VPN
- Малого офиса с 50–400 устройствами
- IP-телефонии и VOIP за NAT
- Использования Linux/Windows/macOS/iOS/Android клиентов **без установки VPN-клиента** на каждом устройстве

## Возможности

### 🎯 VPN Manager — несколько конфигов в одной панели

Загружаете несколько `.conf` файлов от VPN-провайдеров — выбираете один активный. Поддерживаются **WireGuard** и **OpenVPN** в одном интерфейсе.

- **Drag-and-drop сортировка** по приоритету
- **Inline-переименование** — двойной клик на имени
- **Bulk-операции** — выделил несколько, удалил одной кнопкой
- **Auto-rollback** — если новый конфиг не поднялся за 15 секунд, возврат на предыдущий
- **Метаданные** парсятся автоматически: тип (WG/OVPN), сервер, порт, протокол

Конфиги хранятся в `/var/www/vpn-configs/` с правами `770 root:www-data` — Apache имеет доступ только через PHP, не напрямую.

---

### 🔄 Failover — переключение на резерв при падении

Назначаете один конфиг **primary**, остальные — **backup**. Если primary падает, Health Check daemon автоматически переключается на следующий по приоритету. Когда primary восстанавливается — возврат на него.

Два режима:

| Режим | Поведение | Когда использовать |
|---|---|---|
| **Мягкий** (default) | Сначала пробует перезапустить активный конфиг, только потом переключается на backup | Стабильная сеть, редкие сбои — экономит время на switching |
| **Агрессивный** | Сразу переключается на backup при первом же сбое | Критичная нагрузка, нужно минимальное время простоя |

История переключений в `events.log` с временными метками и причинами.

---

### 🛡 Kill Switch — защита от утечек

При падении VPN весь LAN-трафик **жёстко блокируется** через `iptables FORWARD REJECT`. Реальный IP не утечёт даже на секунду.

**Как работает:**
1. `FORWARD policy` установлено в **DROP** — по умолчанию ничего не пропускается
2. Явно разрешён маршрут `LAN → tun0 → интернет` через NAT
3. Прямой выход `LAN → WAN` заблокирован правилом `REJECT` с ICMP-ответом — по правилу на каждый канал из `WAN_LIST`

**Self-healing:** Health Check daemon следит за наличием Kill Switch правил каждые 15 секунд. Если кто-то выполнил `iptables -F` — правила автоматически восстанавливаются из `/etc/iptables/rules.v4`.

---

### ❤️ Health Check Daemon — мониторинг 24/7

Долгоживущий процесс (`Type=simple`, не cron-таймер), который реагирует на падения за **~5 секунд**. Запускается через systemd, перезапускается автоматически при крэше.

**Что умеет:**

- **Ping-based monitoring** — проверяет туннель пингом каждые 5 секунд
- **ISP-down detection** — если упал интернет провайдера, не пытается перезапускать VPN (бесполезно). Различает локальный сбой от глобального
- **Warmup phase** — после reboot ждёт 120 секунд стабильности перед оценкой состояния (чтобы не словить false-positive failover)
- **Восстановление iptables** — мониторит Kill Switch правила, восстанавливает при необходимости
- **Журнал событий** — пишет всё в `/var/log/vpn-panel/events.log` для анализа из веб-панели
- **Hash-based reload** — при обновлении скрипта (`md5sum` изменился) перезапускается автоматически

**Логи:** `/var/log/vpn-panel/vpn.log` (текущее состояние) и `events.log` (исторические события).

### 💻 Веб-терминал

Полноценный shell прямо в браузере через **shellinabox**. SSH-клиент не нужен.

- Кастомная **тёмная тема** в фирменных цветах VPN Panel
- Доступ через `/shell/` на порту 80 (HTTP-proxy через Apache, не отдельный порт)
- `localhost-only` биндинг — снаружи недоступен, только через авторизованную панель
- Поддержка `tab-completion`, `Ctrl-C`, `Ctrl-D`, истории команд

Удобно для быстрой диагностики через смартфон без таскания SSH-ключей.

### 🔀 Несколько провайдеров

Каналы описываются в `/etc/vpn-panel.conf` списком с приоритетом:

```
WAN=ens33
WAN_LIST=ens33 ens36
```

`WAN_LIST` — порядок предпочтения, `WAN` — активный сейчас канал. Каждому выделяется своя таблица маршрутизации (`100 + приоритет`) и правило `from <адрес> lookup <таблица>`, иначе ответы уходили бы не тем каналом, которым пришёл запрос.

**Отработка отказа двухуровневая.** Health Check сначала проверяет канал и только потом трогает VPN: если основной провайдер лёг, панель переключается на резервный и перезапускает туннель, а не крутит VPN-конфиги впустую. Возврат на основной канал — после трёх подряд успешных проверок, чтобы не мигать на нестабильной линии. Каждое переключение попадает в журнал событием `wan_switch`.

Управление из консоли:

```bash
sudo vpn-panel-routing status
sudo vpn-panel-routing free
sudo vpn-panel-routing add-wan ens36
sudo vpn-panel-routing set-active ens36
```

То же самое доступно на странице «Сеть» в панели.

### 🌐 Сетевые настройки через UI

Без ручной правки `/etc/netplan/*.yaml`:

- Переключение WAN между **DHCP** и **Static IP**
- Список каналов в интернет: приоритет, адрес, шлюз, состояние; переключение активного, добавление и удаление провайдера без переустановки
- Изменение DNS-серверов (по умолчанию 1.1.1.1 + 8.8.8.8)
- Применение через `netplan try` с автоматическим rollback при потере связи (90 сек)
- Локальный DHCP/DNS через **dnsmasq** для LAN
- DHCP lease **72 часа** (3 дня) — IP-телефоны реже обновляют адрес

**VOIP-оптимизации:**
- `nf_conntrack_max=524288` — таблица connection tracking для 400+ устройств с SIP
- UDP timeouts настроены для быстрого release SIP-сессий
- **SIP ALG отключён** через `modprobe blacklist` — ядерный модуль `nf_conntrack_sip` чаще ломает VOIP, чем помогает

### 🔒 Безопасность

| Защита | Реализация |
|---|---|
| **Авторизация** | Root-пароль через PAM (привязка к системному паролю — не нужна отдельная БД) |
| **Brute-force на login** | 5 попыток / 5 минут lockout (PHP-уровень) |
| **SSH brute-force с WAN** | iptables `recent` rate-limit: 10 попыток/60 сек, потом DROP |
| **HTTP flood** | 60 запросов/60 сек на IP, DROP при превышении |
| **LAN whitelist** | Локальная сеть обходит rate-limit — VS Code Remote SSH, IDE-плагины могут открывать сколько угодно соединений |
| **Sudoers** | Минимальный набор: только `systemctl reboot/poweroff`, `netplan try/apply`, конкретные VPN-сервисы. Никакого `ALL=(ALL) NOPASSWD: ALL` |
| **Сессии** | Session ID привязан к IP клиента, тайм-аут 30 минут, регенерация ID при логине |
| **CSRF** | Token-based проверка для всех state-changing операций |
| **PAM faillock** | Soft-режим (`deny=30, unlock=60s`) — закомментирован в `/etc/pam.d/*` для LAN. Brute-force с WAN ловит iptables |
| **Hardening Apache** | `ServerTokens Prod`, `ServerSignature Off` — версии Apache/PHP не светятся в заголовках |

### ♻️ Авто-обновление с миграциями

**Каждый час** cron запускает `/usr/local/sbin/vpn-panel-deploy auto` со случайной задержкой до 10 минут. Что разворачивать — решает `release.conf` в ветке `main` репозитория, общий для всего парка: тег релиза, стоп-флаг, процент канарочной выкатки. Подробности — в [docs/diagnostic.md](docs/diagnostic.md#управление-парком-панелей).

Что делает деплой по шагам:

1. Берёт блокировку — cron и ручной запуск не столкнутся
2. `git fetch --tags` в `/opt/vpn-panel/src` (в веб-корне git не используется)
3. Выбирает релиз: последний тег `vN` для канала `stable`, либо то, что закреплено в `PINNED_TAG`
4. Делает снимок текущего `/var/www/html` в `/opt/vpn-panel/releases/`
5. Выкладывает код и запускает `update.sh` — только миграции, без git
6. Проверяет результат: файлы на месте, apache жив, `login.php` отвечает 200/302. Не сошлось — **откат** на снимок. `diagnostic.sh` при этом только рапортует и на решение не влияет

**Версия одна — номер выпуска.** Одноразовых действий пока нет: обновление сводится к sanity-check блокам. Когда появится изменение, требующее правки уже установленных серверов, в `update.sh` добавляется блок `if [ "$CURRENT_RELEASE" -lt N ]`, где N — номер выпуска, в котором изменение вышло.

**Sanity-check блоки** запускаются при каждом запуске `update.sh`:

- Проверка прав на критичные файлы (`/var/www/settings`, vpn-healthcheck.sh)
- Валидация `/etc/vpn-panel.conf` — если в нём WAN/LAN которых нет в системе, перегенерация через `ip` команды (список каналов `WAN_LIST` и параметры LAN при этом сохраняются)
- Восстановление Kill Switch правил если их нет в `iptables`
- Синхронизация HC daemon при изменении скрипта (md5 hash compare)
- Проверка sudoers (visudo -c)
- Установка недостающих PHP расширений

**Запустить вручную:**
```bash
sudo vpn-panel-deploy deploy
```

**Посмотреть состояние и откатиться:**
```bash
sudo vpn-panel-deploy check
sudo vpn-panel-deploy list
sudo vpn-panel-deploy rollback
```

**Через панель:** Настройки → Обновить панель.

При обновлении **активный VPN не падает** — миграции написаны так, чтобы не трогать запущенный туннель без необходимости.

## Установка

### 1. Подготовка сервера

Чистый Ubuntu 22.04 с двумя сетевыми интерфейсами:

- **WAN** — смотрит в интернет (или в роутер провайдера)
- **LAN** — смотрит в локальную сеть, куда подключаются устройства

> ⚠️ Установщик **сбросит** все правила netplan и iptables. Запускайте только на чистом сервере или сервере, выделенном под VPNPanel.

### 2. Запуск установщика

```bash
git clone https://github.com/linux0programmer/vpnpanel.git && sudo bash vpnpanel/installer/install.sh
```

**Скрипт интерактивный:**

1. Сканирует сетевые интерфейсы и показывает список с IP/state
2. Спрашивает, какой WAN, какой LAN, и предлагает добавить резервных провайдеров на свободные карты
3. Спрашивает режим сети — DHCP, статика или **не менять текущие настройки WAN**
4. Дальше всё автоматом: пакеты, конфиги, файрвол, веб-панель

Режим «не менять» пригодится, когда на WAN уже настроена статика: установщик её не трогает, только проверяет, что адрес и маршрут по умолчанию на месте, и настраивает LAN. Чужие файлы в `/etc/netplan/` не удаляются — весь каталог копируется в `/var/backups/vpn-panel/`, а конфликтующие по интерфейсам файлы отключаются переименованием и возвращаются при полном удалении панели.

Время установки — **5–15 минут** в зависимости от скорости интернета.

### 3. Подключение

После установки:

```
http://10.32.0.1/
```

Логин — пароль root от вашего сервера.

> 📌 IP `10.32.0.1` — это адрес LAN-интерфейса, hardcoded в установщике. Подключайтесь с устройства, физически воткнутого в LAN-порт сервера, либо через WiFi-точку, подключённую к LAN-интерфейсу.

### 4. Загрузка VPN-конфига

В панели: **VPN Manager → "Добавить конфиг"** → загружаете `.conf` от вашего VPN-провайдера → **"Активировать"**.

Через 5–15 секунд туннель поднимется. Все LAN-устройства начнут ходить в интернет через VPN автоматически.

## Системные требования

| Что | Требование |
|---|---|
| ОС | Ubuntu 22.04 LTS или 24.04 LTS — на них проверялось |
| Сетевые карты | минимум две: WAN к провайдеру, LAN в локальную сеть |
| Права | root |
| Интернет | нужен во время установки (пакеты + клон репозитория) |

**Другие версии Ubuntu.** Установщик не откажется работать, но предупредит. Перед тем как что-либо менять в системе, он проверяет, что все обязательные пакеты есть в репозиториях, и останавливается заранее, если чего-то не хватает — так на новом релизе нельзя получить сервер с переписанной сетью и без панели.

Пакеты разделены на две группы:

- **обязательные** — `apache2`, `php` + `php-yaml`, `php-mbstring`, `wireguard`, `openvpn`, `dnsmasq`, `iptables-persistent`, `git`, `curl`, `wget`, `openssh-server`. Если хоть одного нет, установка прекращается до внесения изменений;
- **необязательные** — `htop`, `mtr`, `net-tools`, `resolvconf`, `shellinabox`. Недоступные пропускаются с предупреждением.

Отдельно про **shellinabox**: пакет заброшен апстримом и в новых репозиториях может отсутствовать. Без него панель ставится и работает полностью, кроме раздела «Консоль» — веб-терминала не будет.

Что стоит проверить руками на релизе новее 24.04: применение `netplan` (в свежих версиях он строже относится к правам на свои файлы, а панели нужен доступ на запись), поведение `systemd-resolved`, который установщик отключает в пользу `dnsmasq`, и сохранение правил `iptables` через `iptables-persistent`.

## Установщик: что внутри

`install.sh` — это **не просто `apt install` обёртка**. Это аккуратный bash-скрипт ~1500 строк с продуманной архитектурой:

### Идемпотентность

Можно запускать **повторно** без вреда. При повторном запуске на установленном сервере предлагает меню:

1. **Переустановить** — снести и заново
2. **Обновить панель** — деплой релиза + миграции (без переустановки ОС-пакетов)
3. **Полное удаление** — снять VPN Panel, оставив только базовую систему
4. **Выход**

### Полный лог

Все действия дублируются в `/var/log/vpn-panel/install.log`:

- Юзерские сообщения (`log_info`, `log_warn`) — с цветами в терминале, без ANSI-кодов в логе
- Шум от `apt-get`, `git`, `systemctl`, `iptables` — целиком в лог через FD-редиректы

Если что-то пошло не так — `tail -50 /var/log/vpn-panel/install.log` покажет точную причину.

### Восстановление при падении

- **APT busy** — ждёт до 5 минут пока освободится `dpkg` lock
- **Сломанный dpkg** — автоматический `dpkg --configure -a + apt-get -f install`
- **Битый APT cache** — очистка `/var/lib/apt/lists/partial/` и retry до 3 раз
- **Падение установки пакета** — повторная попытка с `apt-get -f install`
- **Sudoers ошибка** — `visudo -c` валидация перед сохранением (защита от блокировки sudo)

### Защита от netplan-багов

Раньше было: `find /etc/netplan -name "*.yaml" | head -1` — это рекурсивный поиск, который мог зайти в `backup_*` папку и прочитать устаревший конфиг с `eth0` вместо реального `ens33`. **Сейчас** определение интерфейсов идёт через `ip` команды напрямую (читаем актуальное состояние ядра, а не файлы):

```bash
LAN_IF=$(ip -4 addr show | grep "10\.10\.1\.1/" | awk '{print $NF}')
WAN_IF=$(ip route show default | grep -v "dev tun" | grep -oP 'dev \K[^ ]+' | head -1)
```

### Чистое удаление

Опция «Полное удаление» снимает **всё, что поставила панель**, и не трогает чужое:

- Apache, PHP, dnsmasq, shellinabox, iptables-persistent — `apt purge`
- WireGuard и OpenVPN **не удаляются** (могут использоваться другими сервисами) — это явно указывается в сообщении
- Восстанавливается `systemd-resolved`
- Создаётся базовый netplan (DHCP на eth0) — чтобы сервер не остался без сети после очистки

## Обновления

### Автоматически

Cron-задача `0 * * * *` вызывает `/usr/local/sbin/vpn-panel-deploy auto`. Процесс полностью non-interactive и сам себя откатывает при провале проверки:

```bash
sudo vpn-panel-deploy auto
```

Канал обновлений задаётся в `/etc/vpn-panel.conf`:

| Ключ | Значение |
|---|---|
| `CHANNEL` | какую строку `release.conf` читать: `stable` (по умолчанию) или `edge`. Без манифеста — последний тег `vN` либо ветка `main` |
| `PINNED_TAG` | стоять строго на указанном теге |
| `VERIFY_TAGS` | `1` — требовать подписанный тег, иначе деплой отменяется |
| `REPO_URL` | откуда тянуть код |

### Вручную

```bash
sudo vpn-panel-deploy deploy
```

Лог в `/var/log/vpn-panel/update.log`, события — в журнале панели (`update_started`, `update_ok`, `update_failed`, `update_rollback`).

Только миграции, без выкладки кода:

```bash
cd /var/www/html && sudo AUTO_RUN=1 ./update.sh
```

### Через панель

**Настройки → Обновить панель** — кнопка запускает тот же `update.sh` через AJAX. Прогресс отображается в реальном времени.

### Что обновляется

- Код панели (`/var/www/html/` — PHP, JS, CSS)
- Скрипт `vpn-healthcheck.sh` (HC daemon перезапустится автоматически если изменился)
- Конфиги Apache, sudoers — точечные правки через миграции
- Версия в `/var/www/version`

### Что **не** трогается

- `/var/www/vpn-configs/` — ваши VPN конфиги
- `/var/www/settings` — настройки failover/auto-restart/checker
- `/etc/wireguard/`, `/etc/openvpn/` — активные туннели
- DHCP leases, ARP, сетевая конфигурация — только если вы явно изменили их через UI

### Self-healing

Каждый запуск update.sh запускает sanity-check блоки которые **самостоятельно** чинят типовые проблемы:

| Проблема | Sanity-check |
|---|---|
| Права на `/var/www/settings` сбились | Восстанавливаем 666 |
| `/etc/vpn-panel.conf` содержит несуществующий WAN | Перегенерация через `ip` команды |
| Kill Switch правила пропали | Восстановление из `rules.v4` или регенерация |
| HC daemon ссылается на старый путь | Миграция systemd unit |
| Sudoers без правил reboot/poweroff | Добавление недостающих |
| PHP расширения не установлены | Установка `php-yaml`, `php-mbstring` |

## Безопасность

### Что закрыто наружу (на WAN)

| Порт | Что | Защита |
|---|---|---|
| 22 (SSH) | OpenSSH | Rate-limit 10/мин, **только** для WAN. LAN whitelist |
| 80 (HTTP) | Apache (панель + shellinabox proxy) | Rate-limit 60/мин для WAN. LAN whitelist |
| 53 (DNS) | dnsmasq | **Только LAN-интерфейс** — на WAN не слушает |
| 67 (DHCP) | dnsmasq | **Только LAN-интерфейс** |

Всё остальное — DROP по умолчанию.

### Что закрыто на FORWARD

`FORWARD policy DROP` — по умолчанию ничего не пересылается. Явно разрешены только:

```
LAN ──► tun0   (выход в VPN)
tun0 ──► LAN   (ответы — RELATED,ESTABLISHED)
LAN ──► LAN    (внутри-LAN — для DLNA/AirPlay)
LAN ──► WAN    REJECT — Kill Switch
```

### Авторизация

- **Login** — пароль root через `pam_unix`. Никаких отдельных БД с паролями
- **Brute-force защита** — 5 попыток / 5 минут lockout (PHP-уровень, файл `/tmp/login_attempts_*`)
- **Сессия** — привязана к IP клиента, регенерация Session ID при логине, тайм-аут 30 минут
- **CSRF** — токен в cookie + проверка во всех POST/DELETE-запросах

### Sudoers

Нет `ALL=(ALL) NOPASSWD: ALL`. Только конкретные команды:

```
www-data ALL=(ALL) NOPASSWD: /bin/systemctl stop|start|restart openvpn@tun0
www-data ALL=(ALL) NOPASSWD: /bin/systemctl stop|start|restart wg-quick@tun0
www-data ALL=(ALL) NOPASSWD: /usr/sbin/netplan try, /usr/sbin/netplan apply
www-data ALL=(ALL) NOPASSWD: /bin/systemctl reboot, /bin/systemctl poweroff
www-data ALL=(root) NOPASSWD: /usr/bin/id    # для login.php
```

`visudo -c` валидация при каждом изменении — защита от блокировки `sudo` после битого правила.

### Apache hardening

```apache
ServerTokens Prod
ServerSignature Off
```

Версии Apache/PHP не светятся в заголовках и страницах ошибок.

## Масштабирование (большие сети)

Дефолтные настройки рассчитаны на **до ~100 устройств**. Для офисов на 200–400 устройств установщик автоматически выкручивает лимиты:

### dnsmasq

```conf
dns-forward-max=8192      # default 150 — не хватает на 100+ устройств
dhcp-lease-max=2000       # default 1000
cache-size=50000          # default 150 — для крупного DNS-кеша
min-cache-ttl=60          # защита от CDN с TTL=0
neg-ttl=60                # кеш NXDOMAIN
```

### Conntrack

```conf
net.netfilter.nf_conntrack_max=524288          # ~160 MB RAM
net.netfilter.nf_conntrack_udp_timeout=30      # быстрый release UDP
net.netfilter.nf_conntrack_udp_timeout_stream=120
```

При 400 устройствах × 50 connections = 20K baseline + VOIP — запас 10×.

### PAM faillock

В довіреній LAN faillock с deny=3 / unlock=600 раздражает при опечатках в пароле. Установщик ставит **soft-режим:**

```conf
deny=30
unlock_time=60
fail_interval=900
```

Плюс закомментирует `pam_faillock.so` в `/etc/pam.d/*` если он там активен. Brute-force с WAN ловит iptables rate-limit, отдельный слой защиты.

## Troubleshooting

### Веб-панель не открывается

```bash
# 1. Apache работает?
sudo systemctl status apache2

# 2. PHP установлен с расширениями?
php -m | grep -E "yaml|mbstring"

# 3. Веб-папка существует?
ls -la /var/www/html/cabinet.php

# 4. Логи Apache
sudo tail -50 /var/log/apache2/error.log
```

### VPN падает / failover не работает

```bash
# Текущее состояние HC daemon
sudo systemctl status vpn-healthcheck

# Логи мониторинга
sudo tail -100 /var/log/vpn-panel/vpn.log

# Журнал событий (failover, восстановления)
sudo tail -50 /var/log/vpn-panel/events.log

# Активный туннель?
ip link show tun0 && ping -c 3 -I tun0 8.8.8.8
```

### LAN-устройства не получают IP / DNS не работает

```bash
# dnsmasq живой?
sudo systemctl status dnsmasq

# Кто получил DHCP?
cat /var/lib/misc/dnsmasq.leases

# Проверка DNS
dig @10.32.0.1 google.com

# Логи dnsmasq
sudo journalctl -u dnsmasq --since "1 hour ago"
```

### SSH "то работает, то нет"

Поэтому в INPUT есть LAN whitelist. Если всё же есть проблемы, проверьте:

```bash
# Кто в xt_recent (rate-limit бан-лист)?
cat /proc/net/xt_recent/SSH

# Сбросить бан конкретного IP
echo '/10.32.0.5' | sudo tee /proc/net/xt_recent/SSH

# Текущие правила INPUT
sudo iptables -L INPUT -n -v --line-numbers | head -20
```

### Kill Switch не пускает в интернет (после падения VPN)

**Это нормальное поведение** — Kill Switch специально блокирует LAN при падении VPN, чтобы реальный IP не утёк. Чтобы временно открыть прямой выход:

```bash
# 1. Поднять VPN снова через панель — Kill Switch автоматически разблокирует трафик
# 2. Или временно отключить Kill Switch (не рекомендуется):
sudo iptables -P FORWARD ACCEPT
```

Если VPN не поднимается — проверьте конфиг и логи (`vpn.log`).

### Диагностика всего и сразу

В репозитории есть два диагностических скрипта:

```bash
# Общая диагностика (~80 проверок)
curl -O https://raw.githubusercontent.com/linux0programmer/vpnpanel/main/diagnostic.sh && sudo bash diagnostic.sh
```

## FAQ

### Можно ли использовать без LAN-интерфейса (только VPS с одним сетевым)?

Технически нет — установщик требует две сетевые. Это VPN-роутер, не VPN-сервер. Вы не подключаетесь **к** этому серверу как клиент, вы подключаете к нему **локальную сеть**, которая ходит в интернет через VPN.

### Поддерживается ли WireGuard и OpenVPN одновременно?

Да, но **активный туннель** только один. Можно загрузить несколько конфигов разных типов в VPN Manager и переключаться между ними. Failover работает между конфигами разных типов тоже (например primary WG, backup OVPN).

### А WireGuard interface это `wg0` или `tun0`?

`tun0`. VPN Panel использует **единое имя интерфейса** `tun0` для обоих — WireGuard и OpenVPN. Это упрощает iptables правила и Kill Switch (одно правило на оба типа).

### Что с IPv6?

Текущая версия — IPv4-only. IPv6 в roadmap.

### Можно поставить на Debian / CentOS / Arch?

Нет, только Ubuntu 22.04 / 24.04 LTS. Установщик завязан на `apt`, `netplan`, `systemd-resolved`, `iptables-persistent`. Портирование возможно, но не приоритет.

### А если я уже что-то настроил на сервере (Docker, своя сеть)?

Установщик **сбросит** настройки netplan и iptables. Если у вас Docker, своя WireGuard, кастомные сетевые правила — они слетят. Лучше ставить на чистый сервер.

### Сколько ест трафика панель сама по себе?

Очень мало. Панель — это PHP/HTML/JS, статика кешируется через `mod_expires` на 1 год, ассеты gzip-сжимаются через `mod_deflate`. На клиенте ~150 KB однократно при первом заходе, потом долгая работа без новых запросов.

### А что с авторизацией двухфакторной (2FA)?

Не реализовано в текущей версии. На roadmap.

## Удаление

```bash
sudo bash install.sh
# В меню выбрать "Полное удаление"
# Ввести подтверждение: DELETE ALL
```

Удаляется:
- Веб-панель и все её данные (`/var/www/`)
- VPN-конфиги (`/var/www/vpn-configs/`, активные `/etc/wireguard/tun0.conf`, `/etc/openvpn/tun0.conf`)
- DHCP / DNS / Firewall (dnsmasq, iptables правила)
- Apache, PHP, dnsmasq, shellinabox — `apt purge`
- Лог-файлы (`/var/log/vpn-panel/`)
- Cron-задача
- Sudoers правила
- systemd unit для HC daemon

**Не удаляются** (могут использоваться другими сервисами):
- WireGuard и OpenVPN сами по себе — снять вручную: `sudo apt purge wireguard openvpn`

После удаления сервер возвращается в состояние «чистый Ubuntu с базовым netplan на DHCP».
